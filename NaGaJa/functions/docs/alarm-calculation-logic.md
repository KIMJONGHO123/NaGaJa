초기 계산

- 초기 출발 시각 = 수업 시작 시각 - 초기 이동시간
- 기본 준비 알림 시각 = 기본 출발 시각 - 개인 준비시간
- 함수 실행 시각 = 기본 준비 알림 시각 - 30분

최종 계산

- 예측 이동시간 = 지도 API 기본 이동시간 + 혼잡도 보정시간 + 날씨 보정시간
- 최종 출발 시각 = 수업 시작 시각 - 예측 이동시간
- 최종 준비 알림 시각 = 최종 출발 시각 - 개인 준비시간

\----------------------------------------------------------------------------------------------------
예시

1️.기본 정보

수업 시작 시각: 09:00
초기 이동시간: 30분
개인 준비시간: 20분

2️. 초기 계산
초기 출발 시각 = 08:30
기본 준비 알림 시각 = 08:10
함수 실행 시각 = 07:40

3️. 외부 데이터 반영
지도 API 이동시간: 30분
혼잡도 보정: +5분
날씨 보정 (비): +10분

-> 예측 이동시간 = 45분

4️. 최종 계산
최종 출발 시각 = 08:15
최종 준비 알림 시각 = 07:55

- 여유 시간 = (수업 시작 시각 - 현재 시각) - 예측 이동시간

상황 1 (초록)

수업까지 60분 남음 (수업시작시간 9시, 현재시각 8시)

→ 여유 시간 = 20분

수업까지 50분 남음 (수업시작시간 9시, 현재시각 8시 10분)

예측 이동시간 = 45분

→ 여유 시간 = 5분

→ 좀 빡셈 → 노랑

상황 3 (빨강)

수업까지 40분 남음

예측 이동시간 = 45분

→ 여유 시간 = -5분

→ 이미 늦음 → 빨강

# 최종 로직

# 지도 API 다중 경로 + 혼잡도 + 날씨 예보 기반 최종 알람 계산 예시

## 1. 기본 입력값

수업 시작 시각: 09:00
사용자 입력 기본 이동시간: 60분
준비시간: 30분
API 계산 여유시간: 30분

---

## 2. 초기 계산

초기 출발 시각
= 09:00 - 60분
= 08:00

기본 준비 알림 시각
= 08:00 - 30분
= 07:30

API 계산 시각
= 07:30 - 30분
= 07:00

07:00 → 지도 API / 혼잡도 / 날씨 API 계산
07:30 → 기본 준비 알림
08:00 → 기본 출발 예정
09:00 → 수업 시작

---

## 3. 07:00에 지도 API 호출

### 경로 A

버스 노선: 101번
지도 API 기본 이동시간: 55분

### 경로 B

버스 노선: 100-1번
지도 API 기본 이동시간: 58분

### 경로 C

버스 노선: 17번
지도 API 기본 이동시간: 62분

경로가 하나 → 그대로 사용
경로가 여러 개 → 각각 계산 후 선택

---

## 4. 경로별 출발 예상 시각 계산

경로 A = 09:00 - 55분 = 08:05
경로 B = 09:00 - 58분 = 08:02
경로 C = 09:00 - 62분 = 07:58

혼잡도와 날씨는 API 호출 시각인 07:00 기준이 아니라
각 경로의 출발 예상 시각 기준으로 계산한다.

---

## 5. 출발 예상 시각을 기준 시간대로 변환

혼잡도와 날씨는 모두 각 경로의 출발 예상 시각을 기준으로 계산한다.

다만 혼잡도 데이터와 날씨 API는 사용하는 시간 단위가 다를 수 있으므로,
출발 예상 시각을 혼잡도 조회용 시간대와 날씨 예보 조회용 시간대로 각각 변환한다.

### 5-1. 혼잡도 조회용 시간 변환 기준

혼잡도는 시간대별 승차 데이터를 기준으로 계산한다.
따라서 출발 예상 시각을 00분, 30분, 다음 정시 기준으로 변환한다.

00분 ~ 14분 → 해당 정시
15분 ~ 44분 → 30분
45분 ~ 59분 → 다음 정시

예시:

08:05 → 08:00
08:22 → 08:30
08:41 → 08:30
07:58 → 08:00

이번 예시에서는:

경로 A 출발 예상 시각: 08:05 → 혼잡도 기준 08:00
경로 B 출발 예상 시각: 08:02 → 혼잡도 기준 08:00
경로 C 출발 예상 시각: 07:58 → 혼잡도 기준 08:00

따라서 세 경로 모두:

08:00 시간대 승차 데이터를 기준으로 혼잡도를 계산한다.

### 5-2. 날씨 예보 조회용 시간 변환 기준

날씨는 기상청 단기예보 API의 fcstTime을 기준으로 조회한다.
기상청 단기예보의 fcstTime은 보통 정시 단위로 제공되므로, 날씨는 정시 기준으로 변환한다.

00분 ~ 29분 → 해당 정시
30분 ~ 59분 → 다음 정시

예시:

08:05 → 08:00
08:22 → 08:00
08:41 → 09:00
07:58 → 08:00

이번 예시에서는:

경로 A 출발 예상 시각: 08:05 → 날씨 기준 0800
경로 B 출발 예상 시각: 08:02 → 날씨 기준 0800
경로 C 출발 예상 시각: 07:58 → 날씨 기준 0800

따라서 세 경로 모두:

0800 예보 데이터를 기준으로 날씨 보정시간을 계산한다.

---

## 6. 혼잡도 데이터 조회 기준

경로 A 08:05 → 오전8시00 승차 데이터 사용
경로 B 08:02 → 오전8시00 승차 데이터 사용
경로 C 07:58 → 오전8시00 승차 데이터 사용

---

## 7. 실시간 데이터 대신 승차 데이터를 사용하는 이유

혼잡도는 현재 시점인 07:00이 아니라
사용자가 실제로 출발할 시간대의 혼잡도를 반영해야 한다.

실시간 데이터는 현재 상황만 보여주지만,
승차 데이터는 시간대별 이용 패턴을 나타내므로
출발 예상 시각 기준 혼잡도 예측에 더 적합하다.

---

## 8. 혼잡도 기준

0 ~ 10명 → LOW → +0분
11 ~ 30명 → MEDIUM → +3분
31명 이상 → HIGH → +7분

---

## 9. 상위 30% 평균 개념

승차건수: [2, 3, 5, 50, 60]

정렬 → [60, 50, 5, 3, 2]

상위 30% → 2개 선택
→ [60, 50]

평균 = 55
→ HIGH

붐비는 구간만 반영하기 위한 방법

## 12. 날씨 데이터 선택 기준

날씨 데이터는 각 경로의 출발 예상 시각을 날씨 API용 예보 시간으로 변환한 값을 사용한다.

여기서 주의할 점은, 출발 예상 시각을 변환한 값은 기상청 API 요청의 baseTime이 아니라, 응답 데이터에서 특정 예보 시간을 고르기 위한 fcstTime이라는 점이다.

baseTime → 기상청이 예보를 발표한 시각
fcstTime → 우리가 실제로 보고 싶은 예보 시간

예를 들어 함수가 07:00에 실행된다면, 가장 최근 발표 시각인 0500 예보를 조회한다.

baseDate = 20260516
baseTime = 0500

그리고 대중교통 API를 통해 계산한 각 경로의 출발 예상 시각을 날씨 기준 시간으로 변환한다.

경로 A 출발 예상 시각: 08:05 → fcstTime = 0800
경로 B 출발 예상 시각: 08:02 → fcstTime = 0800
경로 C 출발 예상 시각: 07:58 → fcstTime = 0800

이번 예시에서는 세 경로 모두:

0800 예보 데이터 사용

따라서 날씨 API 응답 중에서 아래 조건에 맞는 데이터를 찾는다.

fcstDate = 20260516
fcstTime = 0800
category = PTY, PCP, SNO

## 최종 한 줄 정리

지도 API로 여러 경로를 가져온 뒤,
각 경로의 출발 예상 시각을 계산한다.

출발 예상 시각은 00분, 30분, 다음 정시 기준으로 변환하여
혼잡도 데이터와 날씨 예보 데이터를 같은 시간 기준으로 조회한다.

혼잡도는 경로별로 계산하고,
날씨 API는 1번만 호출한 뒤 각 경로의 시간대에 맞는 예보 값을 선택한다.

마지막으로 지도 이동시간 + 혼잡도 보정시간 + 날씨 보정시간을 더해
최종 이동시간이 가장 짧은 경로를 선택하고,
최종 출발 시각과 최종 알람 시각을 계산한다.
